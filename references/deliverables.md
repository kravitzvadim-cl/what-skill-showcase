# Planning and handoff artifacts

Right-size deliverables to the project. A tiny local prototype rarely needs 12 documents.

Minimum useful outputs:
1. Problem, audience, user goal and measurable success signal in `overview.md`.
2. Prioritized Project DNA in `project-dna.md` with confirmed facts and assumptions.
3. One-page MVP scope, constraints and non-goals; can live in overview for small projects.
4. Architecture sketch only if technical choices matter.
5. Milestone list / next two tasks in `next-tasks.md`.
6. Skill recommendation summary: inspected sources, fit, alternatives, confidence and caveats.
7. Risks, open questions, and approved decisions in `decisions.md`.
8. Visual interfaces only: `design.md` with the existing-system check, owner expectations, a small reference board, directions and their status, and separate quality/compliance results.

For substantial projects, create a PRD, design brief, technical architecture, evaluation plan and implementation slices as separate docs. Never invent pixel-perfect design files when only a design brief was generated. Ask user to approve consequential choices before labeling them final.
